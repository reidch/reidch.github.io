# 几何优先的全自动 3D 场景生成

这是一个面向室内虚拟环境的**全自动、几何优先 3D 场景生成框架**。项目关注的并不只是“生成一张看起来合理的室内图”，而是如何从一个明确的场景描述出发，持续维护布局、层级、相机、深度和物体身份，最终得到能够从新视角观察的持久三维场景。

核心思想很简单：

> **如果空间关系已经由输入明确给出，就不应该让生成模型在后续阶段反复重新猜测。**

因此，显式几何不是一次性的条件输入，而是贯穿资产生成、场景装配、相机规划、多视角生成和最终 3D 重建的持续空间契约。

## 从声明式场景描述开始

系统使用结构化 Scene JSON 作为整个场景的控制入口。它描述：

- 物体与房间的层级关系
- 位置、旋转和尺度
- 近似 scaffold 几何
- 每个对象采用的生成模式
- 稳定的语义 / owner 身份
- 场景级与对象级外观控制

这些信息首先被编译为统一的场景状态。后续模块依据明确的数据契约工作，而不是针对“床”“桌子”“椅子”等物体类别编写专门分支。

因此，同一套代码可以处理不同物体组合、不同布局和不同视觉风格。

## 几何作为持续的空间权威

项目最重要的设计原则，是让显式几何在整个生成过程中保持有效。

基础 scaffold 提供对象的大致形状、尺度和位置。生成模型可以增加局部细节和外观，但不能随意改变对象在房间中的空间角色。

对于生成式 3D 资产，系统会：

1. 根据 scaffold 自动选择代表性观察视角
2. 渲染 RGB、mask 与深度条件
3. 生成具有更多视觉细节的代表图像
4. 将代表图像转换为详细 3D 资产
5. 在模型空间中将生成资产与 scaffold 做相似变换配准
6. 通过原始场景层级重新放回正确的世界位置

如果生成资产不能可靠满足要求，系统使用有界重试与自动 fallback，避免单个失败阻塞整个场景。

## 建筑表面生成

墙面、地板和天花板的几何本身已经明确，因此不需要重新生成几何。

系统把这些建筑表面展开到校正后的二维 surface space，在保持真实比例的条件下生成外观，再将结果精确写回原有三角形表面。

这种方式让生成模型负责“它看起来是什么样”，而已有几何继续决定“它在哪里、尺寸是多少”。

## 自动相机规划

完成场景装配后，同一套几何继续用于自动规划观察相机。

相机系统考虑：

- 真实墙体限定的可用空间
- scaffold 派生的对象碰撞体
- 房间表面的面积加权覆盖率
- 相机之间的重复程度
- 不同相机共同看到的物理表面

系统首先建立安全的候选相机，在碰撞时根据显式几何进行位置修正；随后补充尚未被充分观察的房间区域，直到获得覆盖完整的观察集合。

最终，相机之间依据**共享可见表面面积**连接成 camera graph。

## 几何对齐的多视角生成

每个相机都会导出彼此严格对齐的：

- RGB
- metric depth
- owner / semantic identity
- 几何诊断缓冲

最终视图并不是相互独立生成的。

系统沿 camera graph 从可信视图向外扩展。已经生成的邻居首先通过已知相机参数和 metric depth **重投影到当前目标相机**，再根据深度、可见性和 owner identity 过滤，并将多个可靠参考融合成目标坐标系下的外观条件。

图像生成器随后同时接收：

- 当前目标相机的深度结构
- 已经对齐到目标坐标系的邻居外观
- 场景级视觉风格控制

因此，外观信息可以跨视角传播，但传播过程仍然服从已知几何。

## 可靠性控制与修复

渐进式生成存在一个天然问题：早期视图可利用的可靠邻居较少。

为避免错误不断传播，系统将“生成完成”和“允许作为后续参考”分开管理。结构验证会检查生成结果是否仍与目标几何相符，只有可信结果才进入后续传播。

在第一次图遍历完成后，系统还执行一次有界的 post-hoc repair sweep，重新访问早期参考不足的视图。此时更完整的场景外观共识已经建立，可以改善最初较弱的生成结果。

## 持久 3D 表示

最终得到的 RGB、精确相机和 metric depth 会被导出到深度监督的 3D Gaussian Splatting 后端。

因此，最终产物不只是一组二维图像，而是能够进行 novel-view rendering 的持久三维表示。

完整流程可以概括为：

**Scene JSON → Scaffold Geometry → Generated Assets & Surfaces → Camera Graph → Geometry-Aligned Multi-View Generation → Validation & Repair → Depth-Supervised 3DGS**

## 可控性

项目将**空间布局控制**与**视觉外观控制**明确分开。

层级、transform 和 scaffold 决定场景的空间组织；对象、表面和场景级 prompt 则负责外观。

实验中，一组 Rococo 风格房间和一组 Modern 风格房间共享完全相同的基础布局与评估相机，但最终呈现出明显不同的视觉风格。另一组 Anime-inspired 房间使用不同布局和不同物体集合，却仍通过完全相同的通用管线处理。

这说明系统既可以：

- 在保持布局不变时改变风格
- 也可以在不修改核心代码的情况下处理新的布局

## 实验结果

系统在三个完整室内场景上进行了评估。

在 **72 个训练视图**上，最终 3DGS 的 pooled reconstruction metrics 为：

- PSNR：**33.55 ± 2.01 dB**
- SSIM：**0.9634 ± 0.0080**
- LPIPS：**0.0382 ± 0.0116**

在 **108 个冻结的 novel views** 上：

- metric depth MAE：**0.0748 ± 0.0595 m**
- median depth MAE：**0.0678 m**

在 **72 对相邻视图**的跨视角几何一致性测试中：

- reprojection MAE：**0.0210 ± 0.0137 m**
- reprojection AbsRel：**0.00648 ± 0.00425**

这些数字用于评估当前系统自身的重建质量和跨视角几何一致性。由于相关方法使用的场景与相机轨迹并不完全一致，项目页面中的外部方法结果只作为上下文参考，而不是宣称严格的统一 benchmark 排名。

## 消融实验

四组消融实验分别验证了系统中的关键协调机制。

**独立逐视图生成**会显著降低最终场景的一致性。在其中一个测试场景上，去掉跨视角传播后，训练 PSNR 从 **33.61 dB** 降至 **27.80 dB**，LPIPS 从 **0.0378** 增至 **0.1144**。

**直接使用未经重投影的邻居图像**会把参考视图自身的透视与构图错误带入目标视角。移除 target-space reprojection 后，18 个匹配目标中的严格接受数量从 **18/18** 降至 **10/18**，验证生成尝试次数从 **21** 增加到 **124**。

**去掉 post-hoc repair** 后，一些早期视图虽然结构有效，但由于最初缺少足够参考，会保持较弱的外观一致性。

**用固定 5 cm 局部移动替代直接几何碰撞退出**，则会在紧凑布局中产生严重遮挡相机，说明显式碰撞几何应该直接用于计算有效修正量。

## 工程设计

除了生成质量，项目也把长流程的可恢复执行作为系统设计的一部分。

管线使用：

- 明确的 stage artifacts
- scoped cache keys
- persistent generation workers
- 有界 retry
- 自动 fallback
- 分阶段 completion state
- 可恢复 / 可继续执行的输出

这样，一次资产生成或某个视图生成失败不会迫使整个场景从头开始。

## 当前范围

当前评估聚焦于**静态、单房间室内场景**。系统假设需要保持空间权威性的元素已经具有近似几何。

这意味着它最适合这样的场景：用户、程序化工具或上游 planner 已经知道“想要怎样的空间结构”，而生成模型负责进一步丰富视觉细节。

薄结构、近距离观察、复杂装饰以及弱覆盖区域仍然更困难；图像生成、image-to-3D 和多视角 refinement 也仍具有较高 GPU 成本。

## 项目意义

这个项目的重点不是提出一个新的单独生成模型，而是建立一个**协调层**：

让不同的预训练生成与重建组件共享同一份显式空间事实，并让这些事实持续参与后续决策。

通过这种方式，生成模型可以负责丰富世界，而不用重新决定世界的结构。
